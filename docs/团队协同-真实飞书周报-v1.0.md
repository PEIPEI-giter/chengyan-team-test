# 团队协同：真实飞书周报分析 v1.0

## 目标与范围

将「目标与战略 → 飞书周报同步 → 进展拆解与确认 → 进展分析」改造为真实数据闭环。本版只支持当前用户已获权限的飞书 Docx/Wiki 文档，不新建飞书内容，不修改原周报。

## 验收要求

| 需求 | 实现 | 验收方式 |
|---|---|---|
| 不使用 mock 目标 | 首次进入为空表单；目标、负责人、周期、KR 写入 SQLite | 刷新页面后数据仍存在 |
| 打通真实飞书 | 服务端使用已授权的 user identity 执行 `docs +fetch` | 页面展示真实用户授权状态，文档无权限时返回中文错误 |
| 保留原文和版本 | 保存 document id、revision id、Markdown 原文和同步时间 | 拆解页展示同步原文与 rev 版本 |
| 自动拆解进展 | 从真实原文提取事项，按文本相关性关联目标/KR，识别完成、风险和亮点候选 | 同步后生成可编辑待确认事项 |
| 分析可追溯 | 仅聚合已确认事项，保存结论、来源事项 ID 与当时的事项快照 | 未确认时不能进入分析，旧记录在修改目标或周报后仍可查看 |
| 生成与保存分离 | 「重新生成」只刷新草稿，「保存」才新增不可变的分析记录 | 重新生成后历史数量不变；保存后历史数量增加 1 |
| 记录全程可见 | 周报分析记录固定展示在团队协同模块底部，不依赖当前步骤 | 在步骤 1–4 均能看到相同记录数量 |
| 记录详情可追溯 | 点击记录进入详情，展示结论及当时保存的确认事项快照 | 详情刷新后仍可通过 URL 中的 analysisId 恢复，并可返回列表 |
| 新建内容生效 | 顶部「新建内容」进入空白目标创建状态，保存前不改写当前数据 | 新建状态表单为空、历史仍在；保存目标后进入飞书同步步骤 |
| 异常可恢复 | 加载、同步中、错误、空态均有明确反馈 | 无效表单显示服务端中文校验信息 |

## API 契约

- `GET /api/collaboration`：返回当前目标、飞书来源、最新周报、拆解事项和最新分析。
- `GET /api/collaboration/auth`：校验飞书用户身份是否可用。
- `POST /api/collaboration/goal`：校验并保存目标与 KR。目标变更后，旧拆解和分析失效，需重新同步。
- `POST /api/collaboration/sync`：读取指定飞书文档最新版本，保存原文并生成待确认事项。
- `PUT /api/collaboration/progress`：保存人工调整及确认状态，同时使旧分析失效。
- `POST /api/collaboration/analysis/preview`：仅使用已确认事项生成未保存草稿，不写数据库。
- `POST /api/collaboration/analysis`：重新核对当前已确认事项，新增一条分析及来源快照记录。

所有业务响应遵循 `{code,message,data}`；飞书同步失败保留真实 HTTP 错误状态与中文提示。

## 当前边界

- 本版不在应用内自建后台调度器；同步由页面手动发起，页面不展示未实现的定时频率。
- 自动拆解为可解释的文本规则分析，不调用未配置的外部 AI 服务；所有结论必须经人工确认来源事项后生成。
- 项目中尚未提供具体的真实目标和周报 URL，因此不预填任何业务数据。

# 澄研智库部署说明

更新日期：2026-09-23

## 一、架构与依赖

- 前端：React + Vite。
- 后端：Node.js HTTP 服务，默认端口 `5175`。
- 数据库：SQLite，运行库为 `data/chengyan.db`。
- 飞书：通过本机 `lark-cli` 用户身份读取已获权限的 Docx/Wiki 文档。
- 推荐环境：Windows 10/11，Node.js 20 或更高版本。

## 二、首次安装

```powershell
git clone <仓库地址>
cd <仓库目录>
npm ci
```

首次启动时，如果不存在 `data/chengyan.db`，服务会自动复制 `data/seed/chengyan-test.db` 作为运行库。

## 三、开发模式

```powershell
npm run dev
```

- 页面：`http://127.0.0.1:5174`
- API：`http://127.0.0.1:5175/api/health`
- Vite 会把 `/api` 请求代理到本地 API 服务。

首次打开先使用测试账号登录：

- 管理员：`admin` / `AdminTest#2026`
- 成员：`member` / `MemberTest#2026`

这些密码仅适用于私有测试环境。管理员可在系统的“用户管理”中创建其他测试账号。

## 四、生产模式

```powershell
npm run build
npm start
```

Node 服务会同时提供 `dist/` 静态页面和 `/api` 接口，访问 `http://127.0.0.1:5175`。

局域网测试时，在 PowerShell 中设置：

```powershell
$env:HOST='0.0.0.0'
$env:PORT='5175'
npm start
```

团队成员使用部署电脑的局域网 IP 访问 `http://<部署电脑IP>:5175`。Windows 防火墙放行端口属于系统级变更，应由管理员按公司安全策略执行。

## 五、飞书授权

未配置飞书授权时，商品库和已有测试数据仍可使用，但不能同步新的飞书周报。

需要同步周报的测试者必须：

1. 在本机安装项目约定版本的 `lark-cli`。
2. 使用自己的飞书账号完成用户授权。
3. 确保对目标 Docx/Wiki 文档有读取权限。
4. 在团队协同第 2 步粘贴文档地址并手动同步。

仓库不包含飞书密码、令牌或应用密钥。

## 六、数据库管理

- 测试种子库：`data/seed/chengyan-test.db`，只读基线，不在运行中直接修改。
- 运行库：`data/chengyan.db`，由服务自动创建或从种子库复制。
- 备份：停止写入后复制 `data/chengyan.db`，同时确认不存在未合并的 WAL 变更。
- 重置测试数据：停止服务，将现有运行库移出项目，再启动服务以重新复制种子库。该操作会丢失本机测试期间新增的数据，执行前必须备份。

## 七、健康检查与验收

```powershell
Invoke-RestMethod http://127.0.0.1:5175/api/health
```

预期返回 `code: 200` 且 `database: ready`。随后检查：

1. 未登录访问业务 API 返回 401，管理员和成员账号都能正常登录、退出。
2. 成员看不到用户管理入口，管理员能查看用户列表。
3. 首页和团队协同页面可以打开。
4. 商品库能读取 3 条测试商品。
5. 周报分析记录显示 1 条，详情包含保存时的事项快照。
6. 浏览器控制台没有应用错误。

## 八、更新与回滚

更新前备份 `data/chengyan.db`，然后拉取代码并执行：

```powershell
npm ci
npm run build
npm start
```

若健康检查失败，停止新版本，恢复上一版代码和数据库备份后重新启动。当前项目没有自动数据库迁移回滚工具，因此不能用旧代码直接打开已经发生不兼容结构变化的新数据库。

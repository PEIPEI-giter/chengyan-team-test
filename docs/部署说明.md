# 澄研智库部署说明

更新日期：2026-09-23

## 一、架构与依赖

- 部署单元：整套“澄研智库”，同一站点包含工作台、商品库、团队协同、用户管理及全部 API；无需逐模块分别部署。
- 前端：React + Vite。
- 后端：Node.js HTTP 服务，默认端口 `5175`。
- 数据库：SQLite，运行库为 `data/chengyan.db`。
- 飞书：通过本机 `lark-cli` 用户身份读取已获权限的 Docx/Wiki 文档。
- 运行环境：Windows 10/11 或 Linux，Node.js 20 或更高版本。

## 二、当前团队测试部署

- 测试站点：<http://121.41.88.142:5175>
- 服务器：阿里云 ECS，Ubuntu 22.04 64 位。
- 部署目录：`/opt/chengyan`。
- 运行用户：`peipei`。

- 飞书 CLI：服务器已安装官方 `@larksuite/cli` `1.0.96`，用户身份已验证可用。
- 阿里云安全组：已放行入方向 TCP `5175/5175`。
- 部署应用版本：`eb382e7a98867f80443843486d10b58df7a338e3`。
- 原有 `ideact` 服务继续使用 `8080`，本系统使用独立 `5175`，两者均已验证为 active。

当前公网站点为 HTTP，登录数据不加密传输，因此只能使用测试账号和测试数据。如需长期使用或存放真实周报，应先配置域名、HTTPS 和更严格的安全组来源限制。

服务管理命令：

```bash

journalctl -u chengyan.service -n 100 --no-pager

```

仓库中的 systemd 模板位于 `deploy/chengyan.service`。

## 三、首次安装

```powershell
git clone https://github.com/PEIPEI-giter/chengyan-team-test.git
cd chengyan-team-test
npm ci
```

该仓库是私有仓库，团队成员必须先获得 GitHub 仓库访问权限。

首次启动时，如果不存在 `data/chengyan.db`，服务会自动复制 `data/seed/chengyan-test.db` 作为运行库。

## 五、生产模式

```powershell
npm run build
npm start
```

Node 服务会同时提供 `dist/` 静态页面和 `/api` 接口，访问 `http://127.0.0.1:5175`。

这里启动的是整套系统：商品库、数据清洗、团队协同和用户管理共用同一个访问地址、Node 进程和 SQLite 数据库。

局域网测试时，在 PowerShell 中设置：

```powershell
$env:HOST='0.0.0.0'
$env:PORT='5175'
npm start
```

团队成员使用部署电脑的局域网 IP 访问 `http://<部署电脑IP>:5175`。Windows 防火墙放行端口属于系统级变更，应由管理员按公司安全策略执行。

### 公网部署前置条件

若需要团队从公司网络之外访问，请准备：

1. 一台可运行 Node.js 20+ 的 Linux 或 Windows 服务器；
2. 持久化磁盘，用于保存 `data/chengyan.db`；
3. HTTPS 域名或安全的公司 VPN/内网穿透方案；
4. 服务器侧独立的飞书授权方式。当前 `lark-cli` 用户授权跟随运行服务的机器，不能直接复用开发电脑的授权文件；
5. 定期备份 SQLite 数据库，并确保只有一个应用实例写入该文件。

不推荐部署到 GitHub Pages、纯静态 OSS 或无持久磁盘的 Serverless 平台，因为这些平台无法同时承载 Node API、SQLite 写入和本机飞书授权。

## 六、飞书授权

未配置飞书授权时，商品库和已有测试数据仍可使用，但不能同步新的飞书周报。

当前阿里云共享测试环境已在 `peipei` 运行用户下完成服务器端授权，团队测试者无需在自己电脑上安装 CLI。飞书文档的可读范围取决于服务器上已授权账号拥有的文档权限。

自行部署新环境时，部署管理员必须：

需要同步周报的测试者必须：

1. 在运行 Node 服务的同一系统用户下安装项目约定版本的 `lark-cli`。
2. 在该系统用户下完成飞书应用配置和用户身份授权。
3. 确保对目标 Docx/Wiki 文档有读取权限。
4. 在团队协同第 2 步粘贴文档地址并手动同步。

仓库不包含飞书密码、令牌或应用密钥。

## 七、数据库管理

- 测试种子库：`data/seed/chengyan-test.db`，只读基线，不在运行中直接修改。
- 运行库：`data/chengyan.db`，由服务自动创建或从种子库复制。
- 备份：停止写入后复制 `data/chengyan.db`，同时确认不存在未合并的 WAL 变更。
- 重置测试数据：停止服务，将现有运行库移出项目，再启动服务以重新复制种子库。该操作会丢失本机测试期间新增的数据，执行前必须备份。

## 八、健康检查与验收

```powershell
Invoke-RestMethod http://127.0.0.1:5175/api/health
```

预期返回 `code: 200` 且 `database: ready`。随后检查：

1. 未登录访问业务 API 返回 401，管理员和成员账号都能正常登录、退出。
2. 成员看不到用户管理入口，管理员能查看用户列表。
3. 首页和团队协同页面可以打开。
4. 商品库能读取 3 条测试商品。
5. 周报分析记录显示 1 条，详情包含保存时的事项快照。
6. 浏览器控制台没有应用错误。
7. `/api/collaboration/auth` 返回 `connected: true` 且 `status: ready`。
8. 当前飞书周报可以用用户身份读取；2026-09-23 验证时读取到修订版 6、正文 1,772 个字符。
9. 真实分析预览基于 30 条已确认事项生成，返回 4 组进展和 4 类风险，预览不新增保存记录。

## 九、更新与回滚

更新前备份 `data/chengyan.db`，然后拉取代码并执行：

```powershell
npm ci
npm run build
npm start
```

若健康检查失败，停止新版本，恢复上一版代码和数据库备份后重新启动。当前项目没有自动数据库迁移回滚工具，因此不能用旧代码直接打开已经发生不兼容结构变化的新数据库。
